# CLAUDE.md

Stack, structure and commands are in [README.md](README.md). This file covers the conventions that aren't obvious from the code.

## Versioning

- Bump the **patch** version (third number, `1.7.0` → `1.7.1`) by default.
- Bump minor or major only when Edgar says so explicitly.

## Releases (Gitflow)

The production branch is `master`, not `main`. Work lands on `develop`.

1. Commit the pending work on `develop` (Conventional Commits, authored by Edgar, no Claude attribution).
2. `git checkout -b release/x.y.z develop`
3. `npm version x.y.z --no-git-tag-version`, then commit `chore(release): bump version to x.y.z`.
4. Merge into `master` with `--no-ff` and the message `chore(release): merge release/x.y.z into master`, then add an annotated tag: `git tag -a vx.y.z -m vx.y.z`.
5. Merge into `develop` with `--no-ff` and the message `chore(release): merge release/x.y.z into develop`, then delete the release branch.
6. Don't push. Give Edgar the command: `git push origin master develop vx.y.z`.

## Design conventions

- The whole site is a terminal: sections are command output (`fastfetch`, `ls -l`, `lazygit`, `mail`), and everything uses one font, Geist Mono.
- Colors only come from the tokens in `src/styles/global.css`. Dark mode is the `dark` class on `<html>`, so components need no dark overrides.
- Red (`--accent`) is the primary color.
- Decoration is made of characters (ASCII/ANSI art, the star sky), never images.

## ASCII art

The hero and footer art are generated by `scripts/ascii-art.py` (Python + Pillow) into the JSON files in `src/data/`. Its flags (`--ansi`, `--light`, `--line`, `--palette`) are described in its docstring. Regenerate the JSON with the script instead of editing it by hand.
